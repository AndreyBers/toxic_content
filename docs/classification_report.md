# Отчёт по классификации текстов HateXplain

## 1. Датасет

Для эксперимента использовался англоязычный датасет HateXplain.

Исходный набор содержит 20 148 сообщений из Twitter и Gab. Для каждого сообщения имеется разметка трёх аннотаторов по трём классам:

- `hatespeech`;
- `offensive`;
- `normal`.

После исключения сообщений, для которых невозможно определить класс по большинству голосов, осталось 19 229 объектов.

Дополнительно для основного эксперимента использовались сообщения с полным согласием трёх аннотаторов. Такой подход позволил уменьшить влияние неоднозначной разметки.

### Покрытие и состав

Сообщения в датасете в основном короткие:

- медианная длина — около 20 токенов;
- около 70% сообщений содержат не более 30 токенов;
- около 98% — не более 50 токенов.

Для классификации использовались три класса: `hatespeech`, `offensive` и `normal`.

### Качество данных

Каждое сообщение размечалось тремя аннотаторами.

При использовании всех объектов с большинством голосов базовая модель показала точность 63,65%. После отбора сообщений с полным согласием 3 из 3 аннотаторов точность той же модели выросла до 76,71%.

Это показывает, что неоднозначность разметки заметно влияет на качество классификации.

Перед обучением также были удалены конфликтующие и повторяющиеся тексты.

### Аудио и качество транскрипций

HateXplain является текстовым датасетом, поэтому исходные данные не содержат аудиофайлов.

Продолжительность записей, частота дискретизации, уровень шума и доля чистых/шумных аудиосегментов для исходного датасета отсутствуют.

В дальнейшем тексты планируется преобразовать в аудио с помощью TTS (Text-to-Speech). В таком случае исходный текст будет использоваться как эталонная транскрипция для синтезированной аудиозаписи.

## 2. Предобработка данных

Перед классификацией была выполнена нормализация текста:

- текст приведён к нижнему регистру;
- удалён служебный токен `<user>`;
- `<number>` и `<percent>` заменены на текстовые обозначения;
- удалены лишние пробелы;
- удалены тексты с конфликтующими метками;
- удалены повторяющиеся тексты.

Стоп-слова и лемматизация не использовались, так как отдельные слова и выражения могут быть важными признаками токсичного содержания.

## 3. Метод классификации

Для классификации использована модель **TF-IDF + LinearSVC**.

Для представления текста одновременно использовались:

- словные TF-IDF n-граммы `(1, 2)`;
- символьные TF-IDF n-граммы `(3, 6)`.

Параметры итогового классификатора:

- `C = 0.20`;
- `class_weight = "balanced"`.

### Почему выбран этот метод

TF-IDF хорошо подходит для коротких текстов и позволяет учитывать слова и их сочетания, характерные для разных классов.

Символьные n-граммы дополнительно позволяют учитывать части слов, различные варианты написания и особенности токсичной лексики.

LinearSVC хорошо работает с разреженными TF-IDF-признаками, быстро обучается и не использует трансформеры, что соответствует условиям задания.

## 4. Результаты

После подбора параметров лучшая точность на валидационной выборке составила **79,36%**.

После выбора параметров модель была переобучена на объединённых обучающей и валидационной выборках и один раз проверена на тестовой выборке.

Итоговый результат:

- **Accuracy — 78,14%**;
- **Macro F1 — 0,7171**.

Результаты по классам:

| Класс | Precision | Recall | F1-score |
|---|---:|---:|---:|
| `hatespeech` | 0,8490 | 0,8356 | 0,8422 |
| `normal` | 0,8017 | 0,8760 | 0,8372 |
| `offensive` | 0,5477 | 0,4144 | 0,4719 |

## 5. Анализ ошибок

На тестовой выборке неправильно классифицировано 322 из 1473 сообщений.

Наиболее частые ошибки:

| Истинный класс | Предсказанный класс | Количество |
|---|---|---:|
| `offensive` | `normal` | 115 |
| `normal` | `offensive` | 68 |
| `hatespeech` | `normal` | 51 |
| `offensive` | `hatespeech` | 39 |
| `normal` | `hatespeech` | 27 |
| `hatespeech` | `offensive` | 22 |

Самым сложным оказался класс `offensive`.

Оскорбительные сообщения могут быть похожи как на обычные сообщения с грубой лексикой, так и на hate speech. В некоторых случаях для правильной классификации необходимо учитывать контекст, адресата высказывания, иронию и общий смысл сообщения.

TF-IDF и LinearSVC хорошо учитывают слова, сочетания слов и части слов, но хуже работают со сложным контекстом. Это является одним из основных ограничений выбранного подхода.

## 6. Вывод

В работе был реализован полный процесс текстовой классификации HateXplain: подготовка данных, предобработка, обучение модели, подбор параметров и анализ ошибок.

Первоначальная точность базовой модели составляла 63,65%. После отбора данных с более качественной разметкой и улучшения признакового представления итоговая точность на тестовой выборке составила **78,14%**.

Лучше всего модель распознаёт классы `hatespeech` и `normal`. Основным направлением для дальнейшего улучшения является качество распознавания класса `offensive`.
